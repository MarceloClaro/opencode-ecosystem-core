# SPEC-935-R463: Propagação da Cadeia de Custódia ao Ponto de Integração Real

## Objetivo
Consolidar e **propagar para a prática** a Cadeia de Custódia Auditável
(SPEC-935-R462). R462 endureceu a estrutura; R463 conecta o gate ao **ponto de
integração real** — o orquestrador — e aos **auto-registros**, para que QUAISQUER
ciclos novos registrados a partir de agora passem por auditoria externa ao
gerador (condição ii do fator limítrofe, R461). Eleva a `Custódia recente` de
1 (R462) para **2+**.

## O que foi entregue (deltas executados)
| (a) Estrutura | (b) Gate no orquestrador | (c) Auto-registro prático |
|---|---|---|
| `EvolutionCycle` + `merkle_root`/`origin_commit`/`state_merkle_root` | `record_evolution()` roteia 3 caminhos | `synthetic_university()` e demo auditados |
| `record_rejected()` (reject trail) | auditado / reject / legacy honesto | âncora de artefato real |
| auto-hash de disco, `verify_merkle`, `git_head_commit` | `round_id` propagado | verifier distinto (`@auditor.blind`) |
| `report.py` + PDF (pandoc→weasyprint) | fail-closed no registro | sem auditor → legacy (audited=False) |
| `doctor.py` reporta Custódia | contrato canônico R414 ampliado | — |

## MÉTRICA PRÉ-REGISTRADA (gate de aceitação)
**Custódia(%)** = (ciclos com `artifact_hashes` ∧ `external_verdict` ∧
`verifier_identity ≠ gerador`) / total × 100.

- Baseline recente: **1/1 = 100%** (R462).
- Alvo pós-R463: **Custódia recente (R462+) ≥ 2** ciclos auditados (R462 e R463).
- Hipótese falsificável: se o R463 não entrar com veredito externo + hashes +
  verifier ≠ gerador, a propagação NÃO elevou a métrica.

## Critérios de aceitação (gate SDD/TDD)
- [B1] `record_evolution()` aceita `verifier_identity`, `artifact_files`,
      `evidence_trail`, `external_verdict`, `generator_identity`, `round_id`.
- [B2] Com verifier+artefatos ⇒ `record_audited` (eleva Custódia, âncora
      merkle/commit/estado).
- [B3] Gate reprova (verifier==gerador) ⇒ `record_rejected` (reject trail),
      sem elevar Custódia, sem exceção fatal.
- [B4] Sem auditoria ⇒ `record()` legacy com `audited=False` (anti-overclaim).
- [B5] `synthetic_university()` e demo ancoram artefato **real** e usam verifier
      **distinto** do gerador.
- [B6] Teste funcional: auto-registro auditado produz `audited=1`, merkle presente.
- [B7] Contrato canônico R414 inclui `merkle_root`/`origin_commit`/
      `state_merkle_root`.
- [B8] **Registro do ciclo R463 real** via caminho auditado, elevando Custódia
      recente para 2+.

## Escopo / anti-overclaim
- A "aprovação externa" usa **papel auditor distinto** do gerador (`@auditor.blind`),
  mesmo padrão já validado no R462; não é auto-avaliação.
- Artefatos ancorados são **conteúdo real produzido** (arquivos/JSON), não
  inventados.
- Ciclos legados (pré-R463) **não** são reescritos (reescrever seria falsificação).
- Hash prova **ausência de alteração**, não **correção** do conteúdo.
