## Ordem de decisão

1. Existe API, SDK, driver ou especificação oficial que resolva o problema?
   Use-a primeiro.
2. Existe projeto aberto que já faça exatamente o trabalho? Procure por
   produto, fornecedor, protocolo e formato.
3. O projeto é adequado? Verifique finalidade específica, atividade recente,
   linguagem, gerenciador de pacotes, licença e risco de quebra.
4. Leia o código antes de executar. Trate código baixado como não confiável.
5. Registre projeto, commit, licença e motivo da escolha.

## Limites de uso

- Use apenas com contas, dispositivos e dados do próprio usuário.
- Não use para scraping em massa, spam, burla de paywall, DRM ou controle de
  segurança.
- Licença vazia significa todos os direitos reservados; não presuma permissão.
- Cliente não oficial pode violar termos de serviço e bloquear conta.
- Índice desatualizado não prova que o repositório ainda existe.
- Reconstruir algo já resolvido é retrabalho; copiar sem licença é risco.

## Relação com o REA

O REA continua sendo o caminho para analisar artefato, binário, Electron,
Android ou firmware sob evidência. Esta nota só determina a busca prévia e o
registro de proveniência; não substitui o servidor, os providers ou o contrato
de evidência da skill `reverse-engineer-anything`.
