Um caminho de execução

Coordenação com rastreabilidade

O primário coordena a ponte REA. Descoberta de ferramentas e prontidão não demonstram qualidade da análise.

A explicação do recibo é determinística: um LLM não é requisito para ler o resultado.

Guia de execução

Comece em quatro passos

Execute os comandos no terminal, a partir da raiz do OpenCode Core no Ubuntu/WSL. Os exemplos usam a instalação local em .venv.

01

Configure o assistente

Gere o perfil local de agente e os exemplos MCP para Linux e Windows/WSL. O setup informa onde os arquivos foram gravados.

Terminal · Ubuntu/WSL
.venv/bin/python -m marceloclaro.cli rea setup

A configuração aceita modelo e endpoint em loopback. Modelo configurado não significa inferência executada.

02

Inspecione o alvo

Informe um caminho autorizado. A seleção automática considera assinatura e extensão; a prontidão do provedor é conferida na operação.

Substitua CAMINHO
.venv/bin/python -m marceloclaro.cli rea inspect CAMINHO --kind auto --format text

O worker exige namespaces Linux de usuário, rede e PID. Se o isolamento não estiver disponível, a análise é bloqueada.

03

Leia a evidência

Use o caminho do recibo emitido pela inspeção. A explicação reúne achados, identificadores de evidência e limitações do provedor.

Substitua RECIBO
.venv/bin/python -m marceloclaro.cli rea explain RECIBO --format text

Um resultado sem evidência identificada não comprova sucesso. Limitações permanecem na explicação.

04

Conecte um cliente local

Configure o cliente com o perfil MCP gerado pelo setup. O cliente inicia este processo e se comunica pelo transporte stdio.

MCP · processo local
.venv/bin/python -m integrations.rea_assistant_mcp

O cliente precisa conservar a política local. Se enviar os dados à nuvem, esse uso fica fora da garantia do modo local.

Sobre o agente

Inspeção e explicação funcionam sem LLM. O valor padrão modelo-local é um marcador: escolha um modelo instalado com rea setup --model NOME_DO_MODELO. Ative a conversa por rea agent, que usa configuração própria fora do projeto. Confirme a inferência separadamente; OPENCODE_CONFIG sozinho pode ser sobreposto pela configuração do projeto.

Confira a configuração efetiva sem inferência
.venv/bin/python -m marceloclaro.cli rea agent --check

HTML / Snapshot

Estrutura de uma página

Arquivos HTML exportados ou snapshot de URL literal loopback. Não segue redirects, acessa sites remotos ou executa JavaScript da página.

Arquivo local
.venv/bin/python -m marceloclaro.cli rea inspect ./pagina.html --kind auto --format text

Para URL loopback, use o endereço numérico local, como http://127.0.0.1:8000/. O snapshot tem limitações próprias e não é um teste dinâmico do site.

A confiança deve acompanhar a evidência da operação solicitada. A explicação não promove uma hipótese a fato confirmado.

I

Instalação

O componente e sua versão foram localizados. Isso não prova configuração válida nem uma análise concluída.

II

Prontidão

Pré-requisitos e configuração da camada foram conferidos. Ainda é necessário executar a operação e verificar a resposta.

III

Execução

A operação retornou evidência identificada, vinculada ao alvo. O recibo conserva proveniência, achados e limitações.

  • Provedor, versão e operação solicitada.

Limites de uso

Localidade com escopo explícito

A inspeção busca compreender o artefato. Ela não recupera necessariamente o projeto original, nem comprova segurança ou equivalência funcional.

Rede privada do worker

O processo analítico usa namespaces de usuário, rede e PID com loopback privado, sem saída para host ou internet. A ausência dessa condição bloqueia a análise.

O cliente também importa

MCP stdio entrega informações ao cliente local. Clientes que remetem esses dados a serviços de nuvem estão fora da garantia desta configuração.

Provedores comerciais opcionais

IDA, Hopper e JEB exigem licença e configuração do operador. Sem esses requisitos, permanecem pendentes; o inventário não demonstra execução.

Inspeção estática

O alvo não é executado. Snapshots HTML não executam scripts. Os achados não são evidência de comportamento dinâmico ou de reconstrução completa.

Isolamento de rede não é uma sandbox universal de arquivos nem protege contra o proprietário do host. Analise somente artefatos que você tem autorização para examinar.
